# Synthesis actions use the existing owned reconciliation workflow

Status: Accepted

Luma Synthesis can contain actionable claims from independent captures, including
Granola Basic notes without raw transcript capability. The existing reconciliation
engine previously accepted only imported Notion Meeting Note action blocks.

We keep original captures and synthesis persistence separate, and admit an explicit
synthesis source variant into the existing private reconciliation engine. Candidate
identity includes the exact logical meeting, synthesis revision, capture-set digest
and claim digest. Raw imports retain their existing IDs and behavior. Human reviews
supply actionable modality, ownership and a date or explicitly no date; partial
coverage and unresolved contradictions remain visible and block unsupported work.
Correcting claim wording clears earlier action details.

Meeting Intelligence owns candidate admission, canonical search, source fencing,
Human resolution and query projection behind observe/query/conclude. The Discord
edge supplies exact choices and identities, not extraction stages. History remains
in storage; a current read does not disclose candidates from an unproven capture set.

Approved Follow-up Execution derives its Operational Outcome target from the current
Logical Meeting canonical anchor. A retained positive synthesis publication and a
fresh native signed-region/grant check establish the destination. A durable private
source execution fence serializes synthesis revision admission with external work.
Provider-positive receipts are retained before later source failures; uncertain
writes retain the existing positive-only recovery policy. There is no second source
capture ledger and no caller-controlled canonical target setter.
