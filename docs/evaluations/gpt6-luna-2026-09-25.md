# GPT-6 Luna versus GPT-5.6 Luna

[LUM-72](https://linear.app/dayova/issue/LUM-72) tracks this evaluation.

**Internal rollout decision, 25 September 2026:** Use `gpt-6-luna` as the default
for Luma's four-founder internal tool. The evaluation found no new automated
failure relative to `gpt-5.6-luna` on the paired cases and estimated much lower
cost. This is a pragmatic owner decision, not a claim of proven quality parity:
the run used the existing synthetic development corpus, one response per case,
and no independent human-labeled holdout or completed semantic review. Keep
the $30 monthly cap, monitor actual use, and track the shared correctness defect
under [LUM-71](https://linear.app/dayova/issue/LUM-71).

The frozen two-model manifest is
[`evals/models/openai-luna-generation-comparison.json`](../../evals/models/openai-luna-generation-comparison.json).
Both models used the same Luma provider-comparison prompt, structured-output
schema, `medium` reasoning effort, 4,096-token output cap, 45-second timeout,
seed 53, and 24 cases in 23 scenario groups. The [full report](../../evals/results/2026-09-25-gpt6-luna/report.json)
and [machine summary](../../evals/results/2026-09-25-gpt6-luna/summary.json)
retain the frozen input cases, request hashes, model responses, usage and
automated grades. There
were 48 dispatched calls and no API/transport failures. All provider-returned
model IDs matched the requested IDs.

| Measure                              | GPT-5.6 Luna | GPT-6 Luna |
| ------------------------------------ | -----------: | ---------: |
| Valid structured outputs             |        24/24 |      24/24 |
| Cases passing every automated check  |        23/24 |      23/24 |
| Observed critical automated failures |            1 |          1 |
| Estimated uncached token cost        |    $0.038741 |  $0.017100 |
| Median response time                 |       6.64 s |     8.50 s |
| 95th-percentile response time        |      15.70 s |    17.82 s |

GPT-6 Luna used about **56% less estimated token spend** on these exact calls,
while its median latency was about **28% higher**. The cost figures use
provider-reported token counts and the published Standard uncached input/output
rates; they are estimates, not a provider invoice or a transaction in Luma's
production budget ledger. The prior four-request smoke test estimated $0.003808
for both models together; the diagnostic repeat below estimated another $0.012693.
Across these three bounded runs, the total estimate was about $0.0723.

Both models failed the same critical `revised-decision` check: they labeled Sam
an objector to Tool Atlas when Sam described a correction after a shared vote,
without evidence of Sam's personal objection. This is a product defect, not a
GPT-6-specific regression. The original full run exited with code 2 because of
those failed checks, despite every API call returning a valid output.
[LUM-71](https://linear.app/dayova/issue/LUM-71) tracks the shared defect and
the unresolved-owner follow-up behavior below.

After inspecting the original answers, a separate **targeted diagnostic** ran
three additional repetitions of `revised-decision` and
`unidentified-speaker-commitment` for each model (12 calls). In the first case,
the old model made the same objection mistake on 3/3 repeats; GPT-6 Luna made it
on 2/3. In the second, both models sometimes proposed a `create-work-item`
follow-up with no assignee even though the speaker identity was explicitly
unresolved (GPT-5.6 Luna 2/3, GPT-6 Luna 3/3). Such proposals still require
Luma's Human approval; the evaluator does not demonstrate that an external work
item was created. This diagnostic was selected after observing the full run and
must not be pooled into an unbiased overall quality score.

The automated checklist does not resolve all semantic differences. For example,
GPT-6 Luna omitted some extra decision records that GPT-5.6 Luna emitted, and
its unresolved-owner follow-up behavior deserves review. No human review verdicts
were supplied. A 23/24 tie on this synthetic set is not evidence of equal quality
on real Dayova conversations; the reported bootstrap interval for the automatic
difference is not a production promotion gate.

The shared correction-versus-objection and unresolved-owner follow-up errors
remain open work. Observe founder feedback, latency, real costs and grounded
Discord/Linear/Notion behavior in internal use. The runtime now has a verified
per-model price entry for `gpt-6-luna`; an unpriced override still fails closed.
Keep the provisional $30/month total limit and compare ledger usage with
provider billing. An existing explicit `LUMA_REASONING_MODEL_NAME=gpt-5.6-luna`
override continues to use the previous model until updated.
