# Imported Meeting understanding

Accepted Notion Meeting Note transcripts now enter Meeting Intelligence's normal
`observe` analysis. This produces Evidence-grounded decisions, Action Items,
questions, risks and suggested Follow-up Intents. It preserves provider summaries,
notes and original transcripts as separate immutable Evidence; it does not replace
the source or create a synthetic transcript. Names embedded in a transcript do not
become verified speakers or confirmed owners. Human replacements remain authoritative.

The main runtime enables this path when organizational context includes the dedicated
read-only Notion configuration and the explicit sharing policy grants the exact page
to the four founders. The configured page must expose exactly one complete, ready
Meeting Note root. Missing or ambiguous roots, partial captures and unavailable
transcripts do not silently become complete understanding. An empty transcript may
be admitted for source review but does not trigger model analysis. The separate
Notion observation-proof host remains a source-only host; it does not activate paid
analysis in a second store.

Before using a capture, the source access adapter checks the current ledger head,
the explicit sharing grant, and a fresh exact-page read with a dedicated read-only
credential. The live capture must match the immutable source snapshot. It checks
the ledger and policy again after reading. Provider content, page/root identity,
transcript capability or permission changes therefore invalidate the proof. These
reads never update provider content or invent a new observed-source revision.

The first authorized analysis admission retains an immutable receipt containing the
source revision/hash, exact Evidence IDs and actual original recipient set. Changing
the current audience cannot widen that receipt. Later analyses, queries, snapshots,
cached conclusions, and each external execution stage revalidate source dependencies.
Unavailable raw-source metadata, candidate reviews and derived claims are withheld
from the current view. The immutable ledger, Observations, Human history and older
Meeting revisions remain stored; withholding is not deletion.

Previously accepted source-only imports can acquire their first explicit grant and
analysis through ordinary ingestion replay. Original grants already recorded for a
source revision cannot be replaced by a broader audience. A durable per-source
analysis attempt is claimed before model dispatch. Concurrent delivery, restart,
invalid output, unknown failure and a source change during a paid call cannot cause
the same source revision to be charged again automatically. A proved pre-dispatch
refusal releases that attempt so the next normal sync can retry after its limit or
configuration is corrected. Source revisions create distinct analysis attempts.
Accepted Evidence remains available in the ledger when model work is deferred;
the returned Meeting update exposes the existing budget/provider/context failure.

Model requests use the main runtime's existing shared USD 30 budget and request
limits. Large transcripts can be refused by those limits; they are never silently
truncated into a supposedly complete capture. No new credential, live source grant,
model call or production process is activated by installing this code.

This is the Notion-only understanding prerequisite under LUM-33. Granola Basic
ingestion (LUM-34), Logical Meeting binding in the ingestion pipeline, multi-capture
claim synthesis and owned Notion Luma Synthesis output (LUM-35) remain separate
required work. It does not mark those acceptance criteria complete.
